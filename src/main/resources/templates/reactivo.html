Programación reactiva

Demostración en el navegador con Reactor (Flux y Mono)

Cada tarjeta ejecuta un ejemplo en el servidor y muestra aquí las señales que emite. Los datos son de ejemplo (no usan la base de datos). Las mismas consultas están en /api/reactivo/....

1. Flux + filter + map

Emite las reservas una por una, conserva las activas y transforma cada una en un texto.

    2. Mono: conteo y consulta por id

    Un Mono emite como máximo un elemento: el total de reservas activas o una reserva concreta.

    Pruebe un id que no exista (por ejemplo 99) para ver el Mono vacío / 404.

      3. Flujo sin resultados

      Un filtro que no deja pasar nada: el flujo termina (onComplete) sin emitir ningún elemento.

        4. Señales onNext y onComplete

        El servidor emite una reserva cada 800 ms y el navegador las recibe en vivo (Server-Sent Events).

        Cancelar a mitad del flujo cierra la conexión y el servidor cancela la suscripción.

          5. Señal onError

          El flujo emite dos reservas y luego falla. onComplete no se ejecuta cuando hay error.

            6. BaseSubscriber: request(1) y cancel()

            El suscriptor pide un elemento por vez (control de demanda) y cancela tras recibir dos.
